# 视觉生成工作流

本页记录自动换皮和自动制作 UI 的最终形态。它只描述工具链和确认边界，不代表包内会直接修改 prefab、图片、图集或 YooAsset。

## 自动换皮

自动换皮面向已有 UI prefab 的改版。输入可以只有 prefab，不强制要求用户手动提供老版本参考图。

默认流程：

1. 从 prefab 自动生成旧版视觉基准图。
2. 根据旧版基准图、扫描报告和风格目标生成改版 Brief。
3. 没有外部参考图时，由 AI 生成风格板或参考图候选。
4. AI 或人工按 Brief 生成新版图片候选。
5. 包内生成 dry-run、执行计划、待补输入、readiness、外部生成输入包、Prompt Pack、单项 Prompt 文件、引用素材清单、宿主执行清单和 manifest。
6. 外部工具按 Prompt Pack 或单项 Prompt 文件、引用素材清单准备新版预览、新图和目标图集输入；清单会按落位目录和引用来源目录分组，并给出验收规则和落位后复跑步骤。
7. 宿主确认后，由宿主执行器真正替换图片、写 prefab 引用、处理图集和 YooAsset。
8. 替换后重新扫描、生成报告并进入人工验收。

旧版视觉基准图优先由 Editor 自动截图生成：临时实例化 prefab，放入标准 Canvas/Camera/CanvasScaler 环境，用 Camera 渲染到 RenderTexture，再导出 `Logs/UIPrefabBaseline_*.png`。只有 prefab 依赖运行时数据、动画、滚动状态、分页状态、后处理或真实游戏相机时，才需要补充运行时截图。

换皮生成的新图可以由 AI 根据风格自行设计，但必须经过预览、尺寸、透明通道、九宫格、图集归属、动态加载风险和宿主确认 gate，不得静默替换工程资源。

## 自动制作 UI

自动制作 UI 面向新 UI prefab 草稿生成。它可以走 AI 生成整图，也可以使用用户提供的参考图和切图。

AI 设计路线：

1. 用户填写新 UI Brief。
2. AI 先生成完整 UI mockup 或多张风格候选图。
3. 用户确认 mockup。
4. 工具输出切图清单、命名、尺寸、透明图、九宫格建议和组件映射。
5. 生成布局草稿 JSON、资源需求清单、布局 dry-run 和宿主生成前确认清单。
6. 宿主确认后，由宿主生成器创建 prefab 草稿。

用户素材路线：

1. 用户提供参考图、PSD/PSB、或已经切好的 PNG。
2. 工具优先使用用户切图，不重复生成同类素材。
3. 工具识别结构、匹配组件候选库、生成布局草稿和资源需求。
4. 通过 dry-run、组件确认和资源确认后，宿主生成 prefab 草稿。

两条路线都必须保留人工确认：AI 生成图、自动切图、资源导入、prefab 创建和资源替换都只在宿主确认后执行。

## 包内边界

- 包内可以生成：旧版基准图、风格 Brief、AI 输入、切图建议、JSON 草稿、CSV/Markdown 报告、dry-run 和确认清单。
- 包内不能直接执行：覆盖 prefab、替换图片、移动资源、修改 SpriteAtlas、修改 YooAsset、写业务脚本绑定。
- 真正写资源的动作必须放在宿主项目，并输出独立执行报告。
